# UI/UX Speed Run — портал хакатону

Готовий адаптивний портал українською мовою для мініхакатону «UI/UX Speed Run: від ідеї до робочого макета».

## Що є в проєкті

- Головна заставка для проєктора та QR-код.
- План заходу на 120 хвилин.
- Сторінка двох команд і вимоги до макета.
- Форма взаємного оцінювання з телефона.
- Сторінка пропозицій конкуренту.
- Сторінка результатів з підсумковими балами та відгуками.
- Панель керівника: етапи, таймер, відкриття/закриття голосування, публікація результатів.
- Демо-режим без Firebase для попереднього перегляду на одному пристрої.
- Firebase Authentication та Realtime Database для синхронізації між пристроями.

## Файли

- `index.html` — усі сторінки порталу.
- `style.css` — оформлення та адаптивність.
- `app.js` — логіка сторінок, таймер, голосування та Firebase.
- `firebase-config.js` — конфігурація вашого Firebase-проєкту.
- `database.rules.json` — стартові правила Realtime Database.

## Частина A. Перевірка демо

1. Розпакуйте архів.
2. Відкрийте папку у Visual Studio Code.
3. Запустіть через розширення Live Server (не відкривайте `index.html` подвійним кліком, бо використано JavaScript modules).
4. У демо-режимі можна переглянути сторінки, запустити таймер і протестувати голосування на одному браузері.
5. Демо-режим НЕ синхронізує дані між різними телефонами/комп'ютерами.

## Частина B. Підключення Firebase

### 1. Створіть проєкт

1. Відкрийте https://console.firebase.google.com/
2. Створіть проєкт, наприклад `ui-ux-speed-run`.
3. Додайте Web App (іконка `</>`).
4. Скопіюйте конфігурацію Firebase SDK.

### 2. Увімкніть Authentication

1. Firebase Console → Build → Authentication → Get started.
2. У Sign-in method увімкніть:
   - Anonymous — для студентів;
   - Email/Password — для керівника.
3. Створіть обліковий запис керівника в Users.

### 3. Створіть Realtime Database

1. Firebase Console → Build → Realtime Database → Create Database.
2. Створіть базу даних.
3. Скопіюйте її URL.
4. Вставте конфігураційні значення у `firebase-config.js`.

### 4. Додайте керівника до дозволених адміністраторів

Після першого входу адміністратора відкрийте Authentication → Users і скопіюйте його UID.

У Realtime Database створіть вузол:

```json
{
  "admins": {
    "ВСТАВТЕ_UID_КЕРІВНИКА": true
  }
}
```

Це потрібно зробити через Firebase Console з правами власника проєкту. Не додавайте адміністраторів через публічний сайт.

### 5. Встановіть правила бази

У Realtime Database → Rules вставте вміст `database.rules.json` і натисніть Publish.

Правила дозволяють авторизованим користувачам читати стан заходу та голоси; керувати станом може лише UID, доданий до `admins`. Кожен Firebase UID може створити один запис голосу в кожній цільовій команді.

**Важливо:** наведені правила обмежують повторний запис за UID, але не підтверджують, до якої команди належить студент. У цій навчальній версії вибір своєї команди у формі є довіреним на рівні інтерфейсу. Якщо потрібне суворе запобігання голосуванню за власну команду, необхідно додати персональні коди учасників із серверною перевіркою (наприклад, Cloud Functions) або заздалегідь створені облікові записи. Анонімний вхід не доводить особу студента.

## Частина C. Публікація на GitHub Pages

1. Створіть GitHub-репозиторій `ui-ux-speed-run`.
2. Завантажте всі файли з архіву в корінь репозиторію.
3. Відредагуйте `firebase-config.js` і збережіть зміни.
4. Відкрийте Settings → Pages.
5. У Build and deployment виберіть Deploy from a branch.
6. Оберіть `main` та `/ (root)`, натисніть Save.
7. Дочекайтеся публікації. Посилання матиме вигляд `https://ВАШ-LOGIN.github.io/ui-ux-speed-run/`.

Додайте домен GitHub Pages до Firebase Authentication → Settings → Authorized domains, якщо Firebase попросить це зробити.

## Як провести захід

1. На комп'ютері викладача відкрийте сайт і перейдіть на головну сторінку.
2. Виведіть її на проєктор у повноекранному режимі (F11).
3. Студенти сканують QR-код.
4. У панелі керівника увійдіть під своїм email і паролем.
5. Запускайте етапи та таймер.
6. Після презентацій відкрийте голосування.
7. Після завершення закрийте голосування та опублікуйте результати.

## Важливі примітки

- QR-код на головній сторінці формується з поточної адреси порталу. Після публікації GitHub Pages він вестиме на опублікований сайт.
- Для синхронізації між пристроями потрібні інтернет і правильно налаштований Firebase.
- Для реального заходу обов'язково протестуйте сайт на двох телефонах і комп'ютері до початку.
- Не використовуйте реальні персональні дані студентів у публічних коментарях.
- Firebase Web API key не є паролем адміністратора; захист забезпечують Authentication і Database Rules. Не публікуйте паролі чи приватні ключі.
- У цій версії оцінки показуються за критеріями та в балах; підсумок команди — середнє значення оцінок, отриманих від учасників іншої команди.

## Що можна доробити наступним етапом

- персональні коди учасників;
- QR-код окремо для кожної команди;
- підтвердження присутності;
- завантаження посилань на макети Figma;
- експорт підсумків у PDF/Excel;
- прихований режим оцінювання до завершення голосування.
